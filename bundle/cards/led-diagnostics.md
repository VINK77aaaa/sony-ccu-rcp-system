# 指示灯灯语诊断 (RCP-3500/3501)

## R — 原文

- CAM PW："按此按钮可从 CCU 向摄像机供电"；四态灯语（第 10 页）：亮起=正在供电；熄灭=已断电且 "即使按下此按钮,仍不会供电"；慢速闪烁=已断电，按下后电源将接通；快速闪烁=摄像机正在启动。
- NETWORK 三态（第 15 页）：亮起=与控制设备相连；闪烁=无法找到控制设备；熄灭=无法与摄像机网络相连或模式为 LEGACY。
- ALARM 四态（第 15 页）：红色亮=本机控制的设备发生错误；绿色亮=本机正在启动；黄色闪烁=本机发生错误、连接了不支持的 USB 设备或时间设置不正确；熄灭=正常。
- CABLE 四态（第 15 页）：绿色亮=接收状态良好；黄色亮=接收电平较低；红色亮=接收电平极低；熄灭=摄像机电源关闭或发生通信故障。
- "当 BARS 按钮亮起时, 系统会优先执行BARS 按钮的功能。" (第 10 页)
- 面板无控制效果的第一甄别：PANEL ACTIVE 与 PARA 指示灯均未亮起时，"无法通过此控制面板控制摄像机"。(第 15 页)
- LCD 故障像素："这些问题并非故障"，有效像素率 "至少达到 99.99%"。(第 3 页)
- "接收到呼叫后, TALLY指示灯会持续闪烁片刻"，持续时间可用 Extend Call 更改。(第 15 页、第 48 页)

## I — 自述

灯语是这台面板排障的第一入口，判读方法是"先分层、再查表、后转介"：

- 四个灯各管一层：CAM PW 管摄像机电源（从 CCU 供电），NETWORK 管本机与控制设备的连接，CABLE 管摄像机↔CCU 的通信电平质量，ALARM 管本机与受控设备的错误。
- 看到现象先归属到某一层，再查该灯的状态→含义对照表得出结论；处置动作本身大多不在灯语里，而在别的能力中（改组网配置、取得面板激活、查备份等）。
- 报故障之前必须先排三类"不是故障"：LEGACY 模式下 NETWORK 熄灭属正常；面板权限态（PANEL ACTIVE/PARA 双灯全灭只是没控制权）；LCD 坏点与 CCD 白点是物理特性非故障。
- 兼容性伪故障也要前置排除：固件不是最新、设备不在支持清单时，功能可能"看起来坏了"。

## A1 — 合成演练

**原书未提供案例**：灯语部分只有"状态→含义"对照表，没有"现象→处置"的完整实例（阶段 0 批判已标注）。以下为**合成演练**（按第 15 页三表可复算）：输入 = NETWORK 亮起 + CABLE 红色亮 + ALARM 熄灭 → 执行 = 逐灯查表分层 → 预期判读：本机↔控制设备连接正常（NETWORK 亮）；摄像机↔CCU 接收电平极低（CABLE 红）→ 故障层在摄像机-CCU 链路；ALARM 灭 = 本机正常且受控设备错误未触发 → 排查方向为 CCA-5/LAN 链路与线长上限（200 m/100 m），处置转 network-setup / specs-reference。

## A2 — 未来触发

**情境**：

1. 开机/播出中："NETWORK 灯一直闪 / ALARM 亮红 / CABLE 变红" 是什么意思、怎么办。
2. 摄像机供电操作：要开机、判断通没通电（CAM PW 四态）。
3. "面板看着正常但拧了没反应"——先分清权限态还是真故障。
4. "监视器怎么调都是彩条"——测试信号输出被 BARS 优先占用。
5. "屏幕有个亮点 / 画面有个白点，是不是坏了，要不要报修"。

**语言信号**：中文——"灯闪 / 灯语 / 指示灯 / NETWORK / ALARM / CABLE / CAM PW / 报警 / 连不上 / 没信号 / 供电 / 彩条 / 坏点 / 白点 / 报修"；英文——"blinking light / indicator / NETWORK ALARM CABLE / CAM PW / no signal / offline / alarm red / dead pixel / power on"。

**相邻区分**（初稿，阶段 3 回填）：

- **mcs-operations**：双灯（PANEL ACTIVE/PARA）全灭 = 权限态非故障——判读入口在本卡，激活/强制激活动作在彼卡。
- **network-setup**：NETWORK 闪烁/熄灭查出是组网配置问题后，改配置的步骤归彼卡。
- **environment-care**：LCD 坏点与白点"非故障"的红线清单收录在彼卡；本卡给出"要不要报修"的甄别与转介（白点→先 ABB→残留走 RPN，转 maintenance-correction）。
- **daily-operation**：BARS/TEST 信号选择的日常操作在彼卡；本卡只在"一直出彩条"类现象时做 f19 判读。
- **file-backup / customization**：ALARM 黄闪涉及"不支持的 USB 设备"与时间设置时，USB 备份与 Extend Call（p61）的设定细节归彼两卡。

## E — 执行步骤

**查表**（状态→含义原样成对，禁止改写）：

CAM PW（第 10 页）：

| 状态 | 含义 |
|---|---|
| 亮起 | 正在供电 |
| 熄灭 | 已断电；即使按下此按钮，仍不会供电 |
| 慢速闪烁 | 已断电；按下后电源将接通 |
| 快速闪烁 | 摄像机正在启动 |

NETWORK（第 15 页）：

| 状态 | 含义 |
|---|---|
| 亮起 | 与控制设备相连 |
| 闪烁 | 无法找到控制设备 |
| 熄灭 | 无法与摄像机网络相连，或模式为 LEGACY |

ALARM（第 15 页）：

| 状态 | 含义 |
|---|---|
| 红色亮 | 本机控制的设备发生错误 |
| 绿色亮 | 本机正在启动 |
| 黄色闪烁 | 本机发生错误 / 连接了不支持的 USB 设备 / 时间设置不正确 |
| 熄灭 | 正常 |

CABLE（第 15 页）：

| 状态 | 含义 |
|---|---|
| 绿色亮 | 接收状态良好 |
| 黄色亮 | 接收电平较低 |
| 红色亮 | 接收电平极低 |
| 熄灭 | 摄像机电源关闭，或发生通信故障 |

**步骤**：

0. **输入契约**（缺失先问，不猜）：①完整灯态观察（哪个灯 / 什么颜色 / 亮-闪-灭）；②当前 CNS 模式（是否 LEGACY 直接改变 NETWORK 熄灭的含义）。
1. **分层定位**：电源层（CAM PW）→ 网络层（NETWORK）→ 链路层（CABLE）→ 设备层（ALARM），逐灯查上表。
2. **处置分支**：
   - CAM PW 慢闪 → 按 CAM PW 供电；快闪 → 等启动完成；熄灭 → 按键也不供电（原书未列明需先满足的其他条件——如实告知，不编造）。
   - NETWORK 闪烁 → 查控制设备 IP/物理链路（转 network-setup）；熄灭且为 LEGACY → 属正常态。
   - CABLE 黄/红 → 查电缆长度与质量（CCA-5 最大 200 m / LAN 最大 100 m，转 specs-reference）；熄灭 → 先查 CAM PW 供电，再查通信。
   - ALARM 黄闪 → 查 USB 设备与时间设置（转 file-backup / daily-operation）；红色 → 受控设备错误，结合 CABLE/NETWORK 定位层级。
   - "拧了没反应"但各灯正常 → 查 PANEL ACTIVE/PARA 双灯（权限态，转 mcs-operations）。
   - "监视器一直出彩条" → BARS 优先：先按 BARS 熄灭，再选 TEST（f19）。
3. **伪故障甄别**（报修前必过）：①固件是否最新、设备是否在支持清单（第 8 页，ce08）；②LCD 固定亮点：有效像素率 ≥99.99%，非故障不报修；③画面白点：先执行 ABB，残留走 RPN 校正（转 maintenance-correction）。
4. **判停**：灯态组合在表中无对应，或表只给电平结论无处置步骤（如 CABLE 红）→ 如实说明原书边界，给出已排除项与转介建议，不编造处置。

**输出契约**：结论 = "灯态组合 → 各层含义 → 故障层级 → 处置/转介能力"，判读逐条标页码。

## B — 边界

- **不要用本卡**：执行组网变更（network-setup）、取得面板控制权（mcs-operations）、白点校正操作本体（maintenance-correction）。
- **失败模式**：把 LEGACY 下 NETWORK 熄灭当故障；把权限态（双灯全灭）当设备故障（p25 互指 mcs-operations）；固件/兼容性伪故障（ce08）；主设备断开后误判面板损坏（ce12，应急动作在 mcs-operations）；LCD 亮点/CCD 白点误报修（ce34）。
- **手册边界（阶段 0 批判）**：灯语表只给"状态→含义"，无完整"现象→原因→处置"决策树；CABLE 红灯仅给"接收电平极低"无处置；CAM PW 熄灭态需先满足的其他条件原书未列明。
- **型号差异**：四张灯语表两型号通用，本卡不区分。

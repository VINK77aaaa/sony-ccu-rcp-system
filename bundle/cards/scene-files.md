# 场景文件管理（面板 1-5 直达 / STORE 存取 / EXPAND 32 文件 / Dissolve）

## R — 原文

（带引号者为原文直接引用；未带引号者为依据 verified 单元整理的原文要点摘录，页码为原文所在页。）

- 面板通道："这些按钮用于注册和读取场景文件"（p11）；操作规则（摘录）：按 STORE 使其闪烁→按编号按钮=注册，完成后 STORE 灯熄灭；STORE 未闪烁时按编号按钮=读取；再按 STORE 取消注册待命（p11）。
- 容量与指示："使用此按钮 (EXPAND) 可显示最多 32 个场景文件"（p11）；场景 1-5 有独立编号指示灯，6 及以后仅 SCENE FILE LED 亮（p11，摘录）。
- 内容边界："场景文件中存储的项目视所连接的摄像机而异"（p11）。
- 菜单通道（p52，摘录）：Scene 菜单 Store→选编号；再按同一编号恢复访问前状态；Dissolve 开启时读取场景文件图像渐变切换（熄灭=立即切换）；Dissolve Speed 数字越大切换时间越长。

## I — Interpretation

场景文件是整套图像参数的"存档槽"，两条通道一个规则：

1. 面板通道最常用：STORE 按钮本质是"写入模式开关"——它闪烁时按编号=把当前状态写进该号（覆盖！），不闪烁时按编号=读取该号。完成与否看 STORE 灯熄灭。
2. 编号 1-5 有独立灯可直达；6 号及以后编号灯不亮是设计行为，要走 EXPAND 显示（容量上限 32 个）。
3. 菜单通道补充两件事：再按同编号可恢复"读取前状态"（后悔药）；Dissolve 让读取时的画面渐变过渡而不是硬切，速度可调。
4. 存的内容项因所连摄像机而异——同一编号在不同机头上承载的参数集不同。
5. 最大的坑是状态机反转：STORE 闪烁态（可能上一位操作者遗留）下按编号，本意读取实际是覆盖写入（此为依手册流程语义的推导，阶段 4 从严实测）。

## A2 — Future Trigger

使用情境：
1. 多机位风格统一：存一套调色、各机调用（"把现在这个调子存起来"/"save this look"/"call scene 2"）。
2. 调 6 号以上场景发现编号灯不亮（"SCENE FILE 灯亮但 8 号灯不亮"/"EXPAND"）。
3. 担心存错覆盖（"会不会把原来的覆盖了"/"STORE 一直在闪怎么回事"）。
4. 读取时想要柔和过渡（"切场景能不能淡入"/"dissolve between scenes"）。
5. 调完想反悔（"能不能回到刚才的状态"/"undo scene recall"）。

语言信号（中英）：场景文件 scene file、STORE、注册/读取 register/recall、编号 1-5、最多 32 个、EXPAND、SCENE FILE LED、Dissolve、渐变切换、恢复访问前状态、覆盖 overwrite。

与相邻能力的区分（初稿，阶段 3 回填）：
- file-backup：场景文件传到 USB（File>Scene Transfer，CAM↔USB）与 RCP 两类设定备份归那边；本卡只管面板/Scene 菜单上的存、取、恢复、渐变。
- white-black-balance：读取场景文件会触发 ABSOLUTE 自动退回相对值——机制与恢复归那边；本卡讲存取动作本身。
- paint-adjustment：场景文件里每个参数（Gamma/Knee/Matrix 等）的语义归那边。
- customization：把场景调出做成自定义按钮不在此手册范围；自定义分配归那边。

## E — Execution

输入契约：
- 必需 (a) 动作：注册/读取/恢复/渐变设定；(b) 目标编号（1-32）；(c) 若为注册：目标编号已有内容时须用户明确确认覆盖——未确认不得执行。
- 缺 (b) 先问编号；用户不确定现状时先读 EXPAND 列表报给他。

步骤：
1. 注册：先看 STORE 灯——若已在闪烁（疑似遗留态）→先按 STORE 取消（防覆盖，见 ce19）→再按 STORE→闪烁→按编号按钮→STORE 灯熄灭=完成（p11）。
2. 读取：STORE 未闪烁时直接按编号。分支：编号 1-5→对应按钮灯亮，直达；6 及以后→编号灯不亮属正常，经 EXPAND 显示后选择（最多 32 个）（p11）。
3. 恢复：再按刚用过的同编号→恢复访问前状态（p52）。
4. 取消：注册待命态（STORE 闪烁）再按 STORE（p11）。
5. 渐变设定：Scene 菜单→Dissolve 开→读取时图像渐变切换；Dissolve Speed 数字越大时间越长（p52）。
6. **判停分支**：任何按编号动作前先报 STORE 灯态——闪烁=写入待命，未闪烁=读取；灯态与用户意图不符时停下核对，不猜测执行。

输出契约：每次操作报告"动作 + 编号 + STORE 灯终态"；注册涉覆盖时报告被覆盖编号的原用途（若已知）并留存确认记录。

## B — Boundary

- 失败模式 ce19[推导]：STORE 闪烁（注册待命）状态下误按场景编号→当前状态写入该编号，原场景文件被覆盖（依手册流程语义推导，阶段 4 从严实测）；规避=按编号前确认 STORE 灯未闪烁，误入待命态再按 STORE 取消。
- 资产边界：场景文件存在摄像机侧，不在 RCP USB Backup 的 [RCP Config] 内（p25 类别定义）——要把场景文件落 U 盘走 File>Scene Transfer（CAM↔USB），归 file-backup 相邻处理。
- 内容边界：场景文件内容项"视所连接的摄像机而异"（p11）——跨机型直接互调同一编号得到的参数集不同，先核对机型。
- 素材缺口（c15）：每页 10 个、页码 1/6 为画面观察值，与 32 上限的换算原书未说明，不作规则使用。
- 反场景：USB 备份/恢复/初始化 RCP 设定→file-backup；读取后旋钮刻度失真→white-black-balance（ABSOLUTE 机制）；调场景里某个参数的含义→paint-adjustment。

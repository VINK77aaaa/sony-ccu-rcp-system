# MCS 多机操作仲裁 (RCP-3500/3501)

## R — 原文

- "只能有一个 RCP 拥有访问权限 (激活)"，以防误操作。(第 8 页)
- "处于激活状态的 RCP 可以操作相应设备。其他 RCP 上会显示值,但不能操作设备"。(第 8 页)
- "通过在未激活的控制面板按下 PARA 按钮,从多个控制器进行并行控制"。(第 8 页)
- "在光圈 / 主黑电平激活状态下, 为了防止误操作,PARA(并行控制)不可用。只有 IRIS/MB ACTIVE 按钮指示灯亮起的 RCP 可以操作设备"。(第 8 页)
- "如果 MCS 模式系统的主设备断开, 则不可实现面板激活操作。在这种情况下,长按 PANEL ACTIVE按钮将强制激活面板"。(第 15 页)
- PANEL ACTIVE 与 PARA 两按钮指示灯均未亮起时，"无法通过此控制面板控制摄像机"。(第 15 页)
- 主/从白平衡 "可用于在旧有连接中使用 CNU (命令网络单元)的系统。LAN 连接不可用"；(第 8 页) 主/从均 ON 时"优先执行主设备设定"。(第 10 页)
- RCP Assign "只能在 MCS 模式中设定。此外,所有连接的设备都必须支持 RCP 分配功能"。(第 47 页)

## I — 自述

MCS 系统里多台面板共享同一批摄像机，靠"两层许可 + 一个仲裁者"维持秩序：

- 整机层：PANEL ACTIVE 灯亮 = 本面板独占该摄像机的操作权，全系统同时只有一台激活，其余面板只显示数值；
- 光圈/主黑层：IRIS/MB ACTIVE 是第二层独立许可（按下 PANEL ACTIVE 也会点亮它），这一层被某台面板独占时，PARA 不可用，只有亮灯面板能调光圈/主黑电平；
- PARA 是并行通道：未激活面板按 PARA 即加入，与激活面板同步控制，适合多岗位协作；
- 仲裁者是主设备（MSU-1500/1000 或 CNA-1）；主设备一断开，常规激活全部失效，唯一旁路是长按 PANEL ACTIVE 强制激活；
- 换受控机位用 RCP Assign（仅 MCS 且全设备支持），切换后会触发旋钮退回相对值模式（属预期）；
- 主/从白平衡是 CNU 旧有连接的遗留功能，LAN 组网（BRIDGE/MCS）下不可用。

## A1 — 书中画面示例 + 合成演练

**书中画面示例**（c13，第 49 页）：RCP Assign 画面显示 "Camera-09 ↔ *Panel-01"——1 号面板改指 9 号摄像机进行中，待控目标编号闪烁；画面含 [Reset]（恢复标准分配）、[All Camera]（显示所有摄像机）、[Set]（应用）。

**原书未提供**激活仲裁与强制激活的完整案例。以下为**合成演练**（可按 p24/p25 规则复算）：输入 = MSU 掉线，3 台面板 PANEL ACTIVE 全灭，转旋钮画面值不变 → 执行 = 任一操作员长按自己面板的 PANEL ACTIVE → 预期 = 该面板强制激活、灯亮、可操作；其余两台仍只读（唯一激活约束依然成立）。注意：此路径绕过主设备仲裁，多人同时长按会争抢控制权。

## A2 — 未来触发

**情境**：

1. 多机位演播："我这台面板拧旋钮没反应 / 只能看数不能调"。
2. 多操作员协作：VD 与灯光/美术要同时跟同一台摄像机的参数。
3. 光圈师报 "光圈拧不动"，或要独占光圈/主黑电平。
4. 主设备（MSU/CNA-1）掉线，全场面板都抢不到控制权。
5. 单面板换控机位："2 号面板改控 5 号摄像机"。

**语言信号**：中文——"激活 / 抢面板 / PANEL ACTIVE / PARA / 并行控制 / IRIS / MB / 光圈控制权 / RCP Assign / 换机位 / 主设备断了 / 强制激活"；英文——"panel active / PARA / parallel control / iris active / RCP assign / master disconnected / force activation / no control"。

**相邻区分**（初稿，阶段 3 回填）：

- **network-setup**：MCS 拓扑搭建、IP/编号配置归彼卡（本卡一句话互指，不展开）；本卡只管系统建好后的控制权仲裁。
- **led-diagnostics**：灯态判读入口在彼卡；判为"双灯全灭权限态"后，取得控制权的动作归本卡。

## E — 执行步骤

**输入契约**（缺失先问，不猜）：①确认系统为 MCS 模式（非 MCS → **判停**：激活/RCP Assign/主从多数机制不适用，组网问题转 network-setup）；②主设备是 MSU 还是 CNA-1；③当前灯态观察（PANEL ACTIVE / IRIS MB ACTIVE / PARA 三个灯的亮灭）。

1. **"面板无响应"第一查**（可判定）：看 PANEL ACTIVE 与 PARA 双灯。
   - 双灯全灭 → 本面板无控制权（原文：无法通过此面板控制摄像机）→ 走 2；
   - PANEL ACTIVE 亮 → 已有整机控制权；若只调不了光圈/主黑 → 查 IRIS/MB ACTIVE 灯，走 3。
2. **取得控制权**：常规 = 按 PANEL ACTIVE 激活（全系统仅一台可激活）；主设备断开且常规激活无效 → **长按** PANEL ACTIVE 强制激活（应急旁路；风险：绕过唯一激活保护，多人同按会争抢）。
3. **并行协作**：未激活面板按 PARA 加入，与激活面板同步控制。**判停**：系统处于光圈/主黑电平激活态时 PARA 不可用——仅 IRIS/MB ACTIVE 灯亮的面板可调光圈/主黑。
4. **换受控机位**（RCP Assign，仅 MCS 且全设备支持）：RCP Config → RCP Assign → 左下方调节旋钮选摄像机编号（[All Camera] 列全部摄像机；[Reset] 恢复标准分配）→ [Set] 应用。切换受控 CCU 会触发 ABSOLUTE 退回相对值模式，旋钮刻度与设定值暂不对应，属预期（重按 ABSOLUTE 恢复）。
5. **主/从白平衡**（仅 CNU 旧有连接）：Multi 菜单选 Master/Subordinate；两端均 ON 冲突时以主设备设定为准。**判停**：Bridge/MCS（LAN）系统 → 功能不可用，改逐台 AWB 或场景文件统一。

**输出契约**：结论 = 灯态（激活/并行/IRIS-MB）+ 已执行动作 + 面板当前权限；排障报告必须带灯态组合。

## B — 边界

- **不要用本卡**：搭建/配置 MCS（network-setup）；灯语表判读（led-diagnostics）；白平衡/场景文件调节本体（white-black-balance / scene-files）。
- **失败模式**：光圈/主黑激活态按 PARA 期望并行调光 → PARA 不生效（ce09）；在 LAN 组网设主/从白平衡 → 功能不工作（ce10）；主设备断开后按常规方式抢激活 → 全部失效，须长按强制激活（ce12）；RCP 编号/IP 重叠导致整系统异常，排多面板诡异问题时列首要怀疑——规划与配置在 network-setup（ce13/ce14 一句话互指）；MCS 下 EXT I/O 的 TALLY 输入被禁用（ce32，与 p66 对应，施工细节见 specs-reference）。
- **手册缺口（needs-review/阶段 4 移交）**：强制激活后主设备恢复流程原书未述；多人同时强制激活的仲裁无原文覆盖。
- **型号差异**：主黑电平调节功能在 RCP-3501 上不可用（其 MB 旋钮可改配其他功能）；RCP-3500 为 IRIS 控制杆 + 主黑电平调节环，RCP-3501 为 IRIS 调节旋钮——IRIS/MB ACTIVE 仲裁涉及 MB 半边时先核对型号。
- **作者盲点（阶段 0 批判）**：手册假设读者已懂多机位仲裁与 Tally 常识，不解释概念本身；激活冲突的现场处置依赖操作员经验，原书只给机制。
